# 목록에서 목표 학회·부제목 편집 · 2026-11-11

프로젝트 목록의 학회 태그와 부제목을 누르면 작은 편집창을 연다. 프로젝트 열기 링크와 편집 버튼은 별도 요소이며, 편집 중 논문으로 이동하지 않는다. 기존 목록의 제목 줄·프로필 아이콘 제거는 유지한다.

## 사용자 동작

- 목표 학회: 기존 프로젝트의 학회를 검색해 선택하거나 이름과 연도를 입력한다. 기존 항목·arXiv·미정 선택은 즉시 저장하고, 직접 입력은 Enter 또는 저장으로 확정한다. 미정은 빈 값으로 저장하며 목록에는 `학회 추가`가 보인다.
- 부제목: 목록에 표시되는 설명을 직접 입력한다. Enter로 저장하며 한글 조합 중 Enter는 저장하지 않는다. 비우면 `부제목 추가`가 보인다. 부제목은 공유되는 하나의 텍스트이며 자동 번역하지 않는다.
- Escape·창 밖 클릭은 저장하지 않고 닫는다. 닫힌 뒤 해당 편집 버튼으로 포커스를 돌려준다. 저장 요청 중에는 닫기·중복 제출을 막는다.
- 저장 성공 후 15초 동안 실행 취소를 제공한다. 학회 변경에는 리버탈 규정 확인 링크도 제공한다. 목표 학회 편집은 리버탈의 적용 규정을 변경하지 않는다.
- 오류는 입력을 보존한다. 동시 수정이 있으면 최신 값을 보여 주고 다시 저장하도록 한다. 실행 취소도 최신 수정이 있으면 덮어쓰지 않는다.
- 모바일 버튼·입력은 44px 터치 영역을 유지한다. 키보드로 화면 높이가 줄면 편집창을 다시 배치한다. 긴 부제목은 모바일 목록에서 두 줄로 제한하고 편집창에는 전체 내용을 표시한다.

## 저장 계약

BackupStore의 기존 SQLite에 `project_metadata(project_id, revision, data)` 테이블을 추가했다. 기존 카탈로그 파일은 기본값이며, 명시적으로 편집한 `venue`, `description`만 공유 저장값으로 우선 표시한다. 새로고침·다른 브라우저·서비스 재시작 후에도 유지한다.

- `GET /api/backups/activity`의 기존 `projects`는 유지하고, 접근 가능한 프로젝트의 `metadata` 배열을 함께 반환한다.
- `GET /api/backups/projects/{backup_id}/metadata`는 현재 버전과 값을 반환한다.
- `PUT`은 `expected_revision`, `changes`와 표시 이름을 받는다. 학회는 최대 80자, 부제목은 최대 500자다. 알 수 없는 필드·제어문자·유효하지 않은 버전은 거부한다. 필드 값 `null`은 해당 덮어쓰기를 제거하여 카탈로그 기본값으로 돌아간다. 빈 문자열은 명시적인 빈 값이다.
- 버전 확인과 저장은 `BEGIN IMMEDIATE` 트랜잭션 안에서 수행한다. 충돌은 409와 최신 값으로 응답한다. 화면도 늦게 도착한 응답을 최신 버전 위에 덮지 않는다.
- 기존 프로젝트 권한 경로를 사용한다. 다른 프로젝트는 보이지 않고 viewer는 수정할 수 없다. 표시 이름을 권한으로 사용하지 않는다. API를 읽을 수 없으면 기존 표시값을 유지하며 편집 기능을 열지 않는다.

목록의 검색은 수정한 학회·부제목도 포함한다. 메타데이터 편집으로 원고 본문이나 리버탈 규정을 수정하지 않는다.

## 검증

Python 검사 95개, 서로 다른 브라우저 검사 17개가 통과했다. 브라우저 기능 검사 9개는 별도 임시 SQLite와 실제 Python API를 사용한다. 공유 저장·새로고침, 기본값 복원, 한글 입력, 텍스트 이스케이프, 기존 학회 선택, 오류 후 재시도, 두 브라우저의 충돌, 오래된 실행 취소, 응답 순서 역전, 읽기 권한과 모바일 배치를 확인했다. 기존 목록의 검색·정렬·언어·활동·논문 탐색도 확인했다.

통과한 검사는 관련 코드 변경이나 구체적인 추가 경계가 있을 때만 해당 범위를 다시 실행했다. 긴 부제목의 두 줄 제한을 보완한 뒤 최종 이미지의 라이트·다크 모바일 검사를 확인했다.

## 운영 기록

운영 DB를 먼저 일관된 SQLite 백업으로 복사하고 `quick_check`를 통과한 뒤 backup과 workspace를 순서대로 교체했다. 원본 카탈로그·원고 파일과 다른 서비스 이미지는 유지했다. 화면은 `hub.js`, `hub.css`, `hub.html`의 자산 버전만 교체했고, 서버는 backup의 `server.py`만 교체했다. 작업 폴더의 별도 CSS 차이와 다른 미배포 변경은 포함하지 않았다.

기존 스냅샷 289개의 ID·본문·내용 해시와 최근 활동은 유지됐다. 자동 백업의 재확인 시간은 정상 갱신될 수 있어 불변 본문과 별도로 비교한다. 배포 중 사용자가 저장한 새 메타데이터도 보존한다.

비공개 릴리스는 `/home/qlab/.local/state/paper-workspace/releases/20261111-project-metadata-9cqbsu6z/`에 보관한다. 이 기능의 배포 설정은 `runtime-final-v2/runtime.compose.json`, 배포 직전 이미지 기록은 `runtime-previous/runtime.compose.json`이다. 이전 이미지는 새 메타데이터 테이블을 사용하지 않으며 공유 값을 삭제하지 않는다. DB 백업에는 비공개 원문이 포함되므로 공개하지 않는다.

최종 확인 중 별도 사이드바 성능 릴리스가 workspace와 bootstrap 자산 버전을 갱신했다. 이를 되돌리지 않고 학회·부제목의 JS·CSS·서버 해시와 캐시 버전이 모두 유지됨을 확인했다. 최신 운영 구성은 그 릴리스를 따르며, 확인 시점의 전체 이미지와 환경은 이 폴더의 `observed-runtime/runtime.compose.json`에도 고정했다. 이전 이미지 기록을 그대로 배포하면 이후의 별도 개선도 되돌릴 수 있으므로 본 기능만 되돌릴 때는 현재 이미지에서 해당 파일 변경만 분리해야 한다. 전체 실행 서비스는 healthy이며 권한 범위가 빈 메타데이터 조회도 빈 배열을 반환한다.

# Sidebar live motion · 2026-11-11

사용자가 이전 최적화 배포 후에도 깜빡임을 보고했다. 기존 코드는 이전 화면과 새 화면의 스냅샷을 마지막 55ms 동안 교차 표시했다. 프레임 간격 개선과 별개로 화면 교체가 남아 있어, 이번에는 사이드바 전환에서 View Transition 캡처와 교차 표시를 제거했다.

원본 편집기와 리뷰 DOM을 계속 표시한다. 본문은 최종 너비를 한 번 적용하고 위치만 220ms 동안 이동한다. 작은 fixed 사이드바만 자체 너비를 보간하며, 본문 텍스트와 PDF는 확대·축소하지 않는다. 헤더의 빈 배경만 크기를 보간한다. 이동 중 본문이 최종 컨테이너 경계에서 잘리지 않도록 하며, 메모와 그 조상에는 transform을 적용하지 않는다. 연속 클릭은 현재 시각 위치를 고정해 읽은 뒤 즉시 반전한다.

검증:

- Chromium 사이드바 12개, Firefox 6개, WebKit 6개, PDF·모바일·리사이저·명암 테마·동작 줄이기 7개로 고유 검사 31개 통과.
- 긴 리뷰의 전환 0/35/110/190/219ms에서 원본 편집기·리뷰 DOM 동일성, 본문 opacity 1, 글자 배율 1, 메모 조상 transform 부재, 헤더 오른쪽 경계를 확인했다. 사이드바에서 화면 캡처 API를 호출하면 실패하도록 검사한다.
- WebKit 반전 검사는 진행 중인 애니메이션을 고정한 위치에서 비교해 측정 도중의 진행 시간 차이를 배제했다. 실제 전환 코드도 반전 전 위치 측정을 위해 진행 중인 애니메이션을 고정한다.
- 합성 데이터와 CPU 4배 저속 Chromium 측정에서 첫 움직임의 중앙값은 이전 약 115ms에서 24ms로 감소했다. 사용자 기기의 표시 FPS를 측정한 결과는 아니다.
- 최신 운영 이미지를 기준으로 이번 변경만 조합한 뒤, 이미지에서 추출한 파일로 사이드바·PDF 검사 13개를 확인했다. 별도로 배포된 화면·리사이저 수정은 보존했다.

화면 서비스의 JS·CSS와 HTML 3개의 캐시 버전만 교체했다. 배포 확인 결과는 아래 비공개 릴리스의 `verification.json`에 기록한다. 운영 계정으로 로그인한 상호작용 검사는 수행하지 않았으며, 브라우저 검사는 배포 파일과 격리된 합성 데이터를 사용했다.

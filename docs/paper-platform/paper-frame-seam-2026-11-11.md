# Paper 프레임 경계 정렬 · 2026-11-11

Paper의 사이드바 너비 조절 영역은 경계 양쪽 5px씩, 총 10px의 드래그 영역을 사용한다. 공통 패널 조절 스타일이 여기에 배경과 양쪽 테두리를 그려 본문 쪽 5px를 덮었다. 헤더와 본문 상자의 위치는 같아도 화면에서는 본문 경계가 어긋나 보였다. Rebuttal에는 이 조절 영역이 없어 같은 현상이 없었다.

데스크톱 Paper의 조절 영역 배경·테두리를 투명하게 유지하고, 마우스·키보드 포커스·드래그 시 실제 경계에만 1px 선을 표시한다. 드래그 영역, 키보드 조절, 저장된 너비와 사이드바 애니메이션은 유지한다.

운영 정적 파일을 사용하는 브라우저에서 수정 전후 라이트·다크 화면을 비교했다. 너비 244px의 사이드바에서 헤더·본문 경계는 모두 x=244이고, 조절 영역도 x=239~249로 동일했다. 수정 후의 경계 픽셀도 확인했다. 기존 브라우저 검사 8개로 1600·1024px의 펼침·접힘 정렬, 실제 드래그와 원문 보존, 키보드 조절·저장 상태, 파일 생성 버튼을 확인했다.

운영 이미지 위에 `project-frame.css`와 두 HTML의 캐시 버전만 변경했다. 별도로 진행 중인 로컬 CSS 변경은 포함하지 않았다. workspace만 교체하며, 리버탈·공유 메타데이터·협업·백업 서비스와 데이터 볼륨은 유지한다.

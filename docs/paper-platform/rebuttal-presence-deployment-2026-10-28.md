접속 표시 범위는 사용자가 지정한 **현재 페이퍼의 Paper와 Rebuttal 전체**다.
다른 페이퍼의 접속자는 포함하지 않는다.

## 동작

- 답변 안에 공동 작업자의 커서, 이름표, 선택 영역을 표시한다. 위치는
  Yjs 상대 좌표를 사용하므로 다른 사람이 앞부분을 수정해도 함께 이동한다.
- 기존 답변 옆 접속 아바타를 유지하고, 우상단 접속 목록에 현재 페이퍼의
  Paper 및 Rebuttal 사용자와 파일·답변·라운드, 편집/보기/자리 비움 상태를 표시한다.
- 목록의 사용자를 선택하면 해당 원고 파일 또는 답변의 위치로 이동한다.
  동일 프로필의 연결은 묶어 표시하며 Paper와 내장 Rebuttal은 같은 연결을 사용한다.
- 숨은 편집기, 다른 답변, 미리보기의 편집 커서는 현재 답변에 남지 않는다.
  연결이 끝난 사용자는 접속 목록에서 제거된다.
- 이름표는 첫 줄에서도 보이도록 공간에 따라 위·아래로 배치한다.
  모바일 접속 목록, 아바타, Escape 및 바깥 클릭 닫기를 확인했다.

## 배포와 검증

화면 서비스만 교체했다. 협업 서버와 나머지 서비스는 재시작하지 않았다.
기존 운영 파일에 이번 기능과 원고 편집 연결 보정만 적용했으며, 작업 폴더의
다른 미배포 UI·언어 전환 변경은 포함하지 않았다. 기존 이미지·설정과 현재
SQLite 사본을 별도 릴리스에 보관했고, 데이터 볼륨과 계정·권한은 유지했다.

로컬에서는 원격 커서·선택·문서 전환·undo 검사, 현재 프로젝트 접속 범위와
Paper/iframe 전환 검사, 모바일·테마·키보드 검사를 통과했다. 실제 운영 파일을
조합한 배포 후보에서도 관련 브라우저 검사 **8개**가 통과했다.

추가 회귀 검사에서 같은 본문의 새 Y.Text가 선택돼도 원고 편집기가 이전
객체에 연결된 채 남는 문제를 재현했다. 객체 변경도 감지하도록 수정했고,
선택 영역·실행 취소·후속 편집 전달이 유지되는 회귀 검사와 기존 두 브라우저

운영 HTTPS에 로그인한 두 독립 브라우저에서 아래 **8개 항목을 확인**했다.

1. 실제로 제공되는 핵심 파일 5개의 SHA-256이 검증한 배포본과 일치한다.
2. Paper 사용자가 Rebuttal의 현재 페이퍼 접속 목록에 나타난다.

4. 접속자를 선택하면 해당 답변의 선택 위치로 이동한다.
5. 미리보기로 전환하면 상대 편집 커서와 선택 영역이 사라진다.

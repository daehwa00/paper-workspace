# 답변 한영 전환의 읽기 위치 유지 · 2026-11-11

답변의 English·한국어 전환은 각 보기의 예전 스크롤 위치를 그대로 보여 주었다. 이제 전환 직전의 읽기 위치를 현재 번역 문단의 대응 정보로 연결한다. 원문 보기와 OpenReview 미리보기 모두 지원하며, 두 모드를 전환하는 기존 동작도 유지한다.

## 위치 연결

- 현재 영어·한국어가 번역 기록과 일치하면 순서가 있는 `segments`에서 위치를 찾는다. 반복 문단은 기록 순서로 구분한다. CodeMirror의 LF와 원문의 CRLF 차이는 읽기 위치 계산에서만 정규화한다.
- 문단 안에서는 상대적인 문자 진행 위치를 사용한다. 이는 읽기 위치의 근사이며, 연결 근거나 인용 검증으로 사용하지 않는다. 두 언어의 길이·어순이 달라 모든 단어의 화면 위치를 일치시키는 것은 아니다.
- 직접 수정한 한국어 등 대응 정보가 유효하지 않으면 문서의 읽기 진행 위치를 기준으로 이동한다. 한국어 초안을 덮어쓰거나 번역 기록을 조작하지 않는다.
- 반복 전환에서는 마지막 대응 위치를 재사용해 반올림에 따른 누적 이동을 방지한다. 사용자가 다른 곳으로 스크롤하면 새 위치를 연결한다. 문서 끝의 스크롤 한계는 유지한다.
- 번역이 진행 중이면 요청한 문단이 도착할 때 위치를 복원한다. 그 전에 직접 스크롤하거나 다른 답변·보기로 이동하면 이전 복원을 적용하지 않는다. 빠르게 원래 언어로 돌아오는 경우도 이전 앵커를 유지한다.
- 모바일에서 한국어 원문 보기의 스크롤 높이를 영어·미리보기와 같은 440px로 맞춘다. 전환 전 페이지 위치를 먼저 캡처하고, 잠깐의 숨김 상태로 페이지가 줄어드는 영향을 피한다.

`rebuttal-reading-position.js`는 읽기 위치만 계산하는 새 모듈이다. 번역·저장·모델 호출을 수행하지 않는다. 미리보기 위치 함수에는 첫 완전한 가시 행을 선호하는 선택 옵션을 추가했으며, 기존 OpenReview 전환의 기본 동작은 동일하다. 변경 전 에디터 소스를 빌드한 결과가 운영 번들과 일치함을 확인한 뒤 번들을 다시 생성했다.

## 검증

위치 계산 단위 검사 6개와 서로 다른 브라우저 검사 17개가 통과했다. 새 언어 전환 검사 9개는 실제 Yjs 문서와 DOM 텍스트 좌표를 사용한다. 양방향·반복 전환, 원문·미리보기, 직접 스크롤, 문서 끝, 모바일 페이지 위치, 지연된 번역, 사용자 입력에 따른 취소, 빠른 전환·다른 답변 이동, 수동 한국어 보존을 확인했다. 영어·한국어·번역 메타데이터가 그대로임도 확인했다.

기존 한국어 갱신·수동 초안 보호와 OpenReview 위치 검사도 통과했다. 새 번들의 기존 위치 함수가 수식·목록·표·코드와 CRLF를 처리하는지 운영 이미지 기반 후보에서 영향 검사 5개를 확인했다. 처음에 문서 끝 근처의 제목을 맨 위에 놓으려던 검사는 실제 최대 스크롤에 도달해 성립하지 않았다. 중간 지점의 정밀 좌표 검사와 문서 끝의 가시성·왕복 위치 검사로 나누어 검증했다.

# 접속자 표시 안정화 · 2026-11-10

Paper·Rebuttal의 접속자 표시 깜빡임과 재연결·퇴장 반영 오류를 수정하고 운영에 반영했다.

## 확인한 원인과 변경

- 커서 이동과 상태 수신마다 아바타·이름·위치의 동일한 텍스트와 속성을 다시 썼다. 사용자별 노드와 텍스트를 유지하며 실제 표시 값이 바뀔 때만 수정한다. Paper의 원격 커서와 이름표도 반복 생성하지 않는다.
- 같은 사용자에게 여러 탭이 있으면 대표 연결이 바뀔 수 있었다. 보이는 탭, 포커스, 편집 상태를 기준으로 선택하고 동점에서는 기존 대표를 유지한다. 사용자 이름이 같아도 식별자가 다른 사람은 구분한다.
- 짧은 재연결 동안 목록을 바로 비웠다. 접속 정보 누락은 최초 누락부터 1,200ms 동안 유지하고, 다른 답변이나 화면으로 이동한 것이 확인되면 해당 답변 목록에서 바로 제외한다. 새 접속과 프로필 변경은 지연하지 않는다. 백그라운드 탭은 자리 비움으로 유지하고 편집 커서는 숨긴다.
- Paper의 위치와 커서가 서로 다른 awareness 메시지로 전송됐다. 한 상태로 함께 전송하며, 숨겨진 공유 Rebuttal iframe은 Paper의 상태를 덮어쓰지 않는다. 수신 알림도 한 작업 안에서 모아 최신 상태를 반영한다.
- WebSocket 연결 상실 시 클라이언트는 상대 상태를 지우면서 상태 번호는 남겼다. 재연결 후 같은 번호의 서버 정보를 무시해 다음 상태 갱신까지 복구가 지연됐다. 전송 연결 상실로 제거된 항목만 기록해 서버의 초기 상태를 다시 수용하고, 본인 상태 번호도 한 번 갱신해 상대에게 재접속을 알린다. 이미 실제 퇴장한 사람의 기록은 되살리지 않는다.
- 서버의 상위 라이브러리는 최초 접속 시에만 사용자 식별자를 소켓에 등록했다. 재연결된 식별자는 갱신으로 분류돼 새 소켓이 끊겨도 퇴장 처리가 누락됐다. 현재 소유 연결이 없는 식별자만 재연결 소켓에 등록한다. 기존 연결이 소유한 식별자는 상태를 중계해도 소유권을 옮기지 않는다.
- 답변 화면 갱신으로 접속자 호스트가 재부착될 때 열린 팝오버를 복구한다. 모바일 크기 변경 직후 열린 명단이 뒤늦은 resize 이벤트로 닫히던 경로는 위치만 다시 계산하도록 바꿨다.

프로필 객체는 복사해 보관하여 표시 이름·색을 직접 변경해도 awareness 변화가 누락되지 않도록 했다.

## 검증

- 공통 컴포넌트 7개: 동일 표시 상태 200회 갱신의 DOM 변경 0건, 사용자 노드·포커스 유지, 프로필·위치 즉시 반영, 대표 탭 안정성, 재연결 유예, 실제 이탈, 호스트 재부착과 팝오버 복구.
- 실제 Yjs WebSocket을 사용하는 새 브라우저 검사 6개: 숨김·복귀, 재연결 양방향 즉시 복구, 진짜 퇴장자 재등장 방지, 이름·색 변경, 답변 이동, 화면 전환의 상태 일관성, 같은 사용자 여러 탭, Paper 커서 노드 유지. 재연결 후 awareness 종료 신호 없이 WebSocket만 닫는 경우도 검증했다. 문서 메타데이터와 버전 이력만 모사하며 공동 편집과 접속 상태는 실제 서버를 사용한다.
- 운영 파일 조합의 기존 브라우저 검사 9개: Paper·Rebuttal 위치 이동, 원격 선택 영역, 다른 라운드·프로젝트 격리, 모바일 크기·밝은/어두운 테마·키보드 조작, 공유 헤더와 답변 접속자 목록.
- 협업 서버 검사 39개 통과.

재연결 복구, 재연결 뒤 소켓 종료, 모바일 resize에서 실패를 재현하고 수정한 뒤 영향받는 검사만 다시 실행했다. 이미 통과한 독립 검사는 반복하지 않았다. 브라우저의 visibility 상태를 통제한 숨김 검사는 모사이며, 포커스와 WebSocket 전파는 실제 브라우저 동작을 사용했다.

## 운영 반영

기존 이미지에 화면 파일 네 개와 협업 서버 파일 한 개만 교체했다. 작업 폴더에 있던 별도 미배포 app.js 수정은 이번 배포에 포함하지 않았다. 클라이언트 번들만 빌드했으며 편집기 번들과 의존성 버전은 교체하지 않았다.

협업 서버를 정상 종료하고 영속 저장소의 압축 백업을 검증한 뒤 `workspace`, `collaboration` 서비스를 교체했다. 기존 데이터 볼륨과 실행 환경을 유지했으며 다른 서비스는 교체하지 않았다. 배포 파일 다섯 개, 양쪽 HTML의 자산 캐시 버전, 전체 서비스의 고정 이미지 ID를 확인했다. 실행 서비스 모두 healthy다.

릴리스·이전 이미지로 되돌리는 설정·협업 데이터 백업과 검증 결과는 `/home/qlab/.local/state/paper-workspace/releases/20261110-presence-stability-_jhzytf1/`에 비공개 권한으로 보관한다. 백업에는 비공개 문서가 포함되므로 공개하지 않는다. 기존 탭을 새로고침하면 화면과 접속 상태 개선이 함께 적용된다.
